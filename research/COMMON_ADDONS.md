# The most common Blender add-ons, to test V2 with (#12)

Gathered 2026-11-22 for #12; #15 works from this list.

## Scope and sources

- **Free (1,000 add-ons)**: the 1,000 most-downloaded add-ons on Blender's extensions platform. Rank and download count come from the
  platform's own listing pages, `https://extensions.blender.org/add-ons/?sort_by=-download_count&page=1` to `page=77` (the tooltip on
  each card gives the exact count). The listing held 1,231 add-ons that day; the cut is rank 1,000 at 993 downloads. The top 1,000 add
  up to 30,382,745 downloads. Id, licence, minimum and maximum Blender version, and the stated permissions come from the platform's
  JSON index, `https://extensions.blender.org/api/v1/extensions/` (1,391 add-ons, 303 themes, 8 asset libraries in it); the two are
  joined on the add-on's page address. Themes and asset libraries are not add-ons and are left out.
- **Paid (24 add-ons)**: no sales ranking is published anywhere. The list is two storefront snapshots, both read 2026-11-22:
  Superhive (formerly Blender Market), `https://superhivemarket.com/categories/addons`, sections "Top Selling Addons this Week" and
  "Top Sellers"; and the "Best-selling paid add-ons" list on `https://learn-blender.org/resources`. Neither gives numbers. 5,000 was
  not worth it (the platform has fewer than 1,400 add-ons, and the tail has under 1,000 downloads each).
- **Blender versions** are the add-on's own `blender_version_min` and `blender_version_max` (`4.2.0+` means no stated maximum).
  V2 tests on 4.2 to 5.3, so an add-on whose minimum is above 4.2 only runs on the later Blenders in #15.

## How "data kept in the .blend" was found

A static scan, not a run. Every archive up to 25 MB was downloaded to a scratch folder (never committed; 972 of 1,000; the other 28
are marked) and its `.py` files searched for: properties registered on `bpy.types.<Type>` (the type is named), `PropertyGroup` and
`PointerProperty` use, node and node-tree classes, `bpy.data.<collection>.new/load` calls (datablocks it makes), writes to disk
(`open(..., 'w')`, `json.dump`, `shutil`, user paths), and depsgraph, undo or save handlers.

Read the column as a pointer for #15, not a verdict:

- `props on WindowManager` (or Screen, Workspace) are session-only, not saved in the .blend; they are listed because they are
  properties but need no history.
- `makes ...` lists datablock collections the code creates; some are temporary.
- `none found` means no such pattern in the add-on's Python (it may still keep ID properties set by key, `obj["x"] = ...`, which
  the scan does not look for); `disk files` marks add-ons that also write files, which V2 cannot put back.
- Compiled add-ons (a `.so` or `.pyd` inside) keep whatever their code keeps; the scan cannot see it.
- `permissions` is what the add-on declares to the platform (files, network, clipboard, camera, microphone).

Tally of the 1,000: 842 keep or make some data a scan can see, 130 show none, 28 not scanned.
